# Hermes Trace Pipe for Open WebUI

Bridge [Hermes Agent](https://github.com/NousResearch/hermes-agent) into Open WebUI and make the agent's reasoning and execution visible inside the chat.

When you chat with Hermes through Open WebUI's OpenAI-compatible endpoint, you only see the final text — the tool calls and their results happen inside the agent. This pipe translates that execution trace into **standard OpenAI chunks** (`delta.reasoning_content`), which Open WebUI renders natively in its collapsible **Thinking** block:

```
🛠️ terminal: uname -a
✅ result:
{"output": "Darwin ...", "exit_code": 0, "error": null}
```

Generated images are attached automatically as markdown (served by a local static server).

## Features

- **Execution trace visible**: every tool call (name + arguments) and its result appears in the Thinking block.
- **Images in chat**: images generated by Hermes (`image_generate`) are attached inline.
- **No Hermes modifications needed**: works with a stock Hermes API server (parses the custom `hermes.tool.progress` SSE events) *and* with a patched server that already emits `reasoning_content` — both modes are handled transparently.
- **Configurable via valves** in the Open WebUI Pipelines UI.

## Requirements

- Open WebUI with the **Pipelines** server running (https://docs.openwebui.com/pipelines/).
- A Hermes Agent instance with its API server enabled (`API_SERVER_ENABLED=true`, `API_SERVER_KEY=...` in `~/.hermes/.env`).

## Installation

### Option A — Install from URL (recommended)

In Open WebUI, go to **Admin Panel → Settings → Pipelines**, add the pipeline URL:

```
https://raw.githubusercontent.com/nicolasramos/hermes-openwebui-pipeline/main/hermes_trace.py
```

### Option B — Manual copy

Copy `hermes_trace.py` into the Pipelines directory (usually mounted at `/app/pipelines` in the `open-webui/pipelines` container), then restart the container:

```bash
docker restart pipelines
```

The model appears in Open WebUI as **`hermes_trace`** (refresh the page if needed).

## Configuration (valves)

| Valve | Default | Description |
|---|---|---|
| `HERMES_BASE_URL` | `http://192.168.1.18:8642/v1` | Base URL of the Hermes API server (OpenAI-compatible) |
| `HERMES_API_KEY` | *(set yours)* | `API_SERVER_KEY` of the Hermes gateway |
| `IMAGES_BASE_URL` | `http://192.168.1.18:8787` | Public URL of the static server serving Hermes' generated images |
| `MAX_RESULT_CHARS` | `1500` | Max characters of each tool result shown in the Thinking block |

Edit them in Open WebUI: **Admin Panel → Settings → Pipelines → hermes_trace → Valves**.

## How it works

1. Open WebUI calls the pipe (`hermes_trace`), which forwards the conversation to the Hermes API server (`/v1/chat/completions`, `stream=true`).
2. The pipe reads the SSE stream and translates:
   - Hermes tool lifecycle events (`hermes.tool.progress`: `running` / `completed`) → `reasoning_content` chunks (🛠️ tool + args, ✅ result).
   - Patched-server `reasoning_content` chunks → passed through as-is.
   - `image_generate` completions → the newest image from the static server is attached as markdown.
   - Final text → standard `content` chunks.
3. Open WebUI renders `reasoning_content` in the Thinking block — no frontend changes required.

### Serving generated images

Hermes saves generated images under `~/.hermes/cache/images/`. To make them reachable from Open WebUI, serve that directory over HTTP (example, macOS):

```bash
python3 -m http.server 8787 --bind 0.0.0.0 --directory ~/.hermes/cache/images
```

(Persist it with launchd/systemd/whatever fits your OS.)

## Gotchas

- **Do NOT set `self.type = "pipe"`** in the Pipeline class. The Pipelines server's `get_all_pipelines()` only registers `manifold` and `filter` types — a pipe with its own `type` attribute is silently skipped and every request returns `404 Pipeline not found`. Leave the attribute out entirely.
- The pipe only shows the tools' *execution trace*. Open WebUI does not execute tools itself (it is a chat client, not an agent runtime).
- Results longer than `MAX_RESULT_CHARS` are truncated in the Thinking block.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `404 Pipeline not found` | Remove `self.type = "pipe"` from the file and restart the Pipelines container. |
| No Thinking block | The stream must contain `delta.reasoning_content`; check the Pipelines logs. Refresh Open WebUI. |
| Images don't load | Make sure `IMAGES_BASE_URL` is reachable from the browser and the static server is running. |
| `401` from Hermes | Wrong `HERMES_API_KEY` (use the `API_SERVER_KEY` from `~/.hermes/.env`). |
